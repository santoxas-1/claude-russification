# Изолированная установка ресурсов русификации (Windows)

Новый `scripts/install-localization.ps1` независим от старого `install.ps1` и не вызывает его.
Требуется Windows PowerShell 5.1 или новее. Сам установщик не повышает права.

## Обнаруженная установка

При подготовке проверены только стандартные каталоги, метаданные EXE и список пакетов Windows:

- Каталог: `C:\Users\20051\AppData\Local\Programs\Claude`
- EXE: `C:\Users\20051\AppData\Local\Programs\Claude\claude.exe`
- FileVersion / ProductVersion: `2.37337.1`
- Ресурсы: `resources\ion-dist` существуют.

Это снимок обнаружения, а не разрешение на установку. Реальное приложение при разработке не изменялось и не перезапускалось.

## Контракт

Обязательны явные `-AppPath` (корень приложения, не `ion-dist`), `-ExpectedVersion`,
`-ExpectedExeSha256` и `-BackupRoot`. Версия читается из FileVersion EXE, SHA-256 сравнивается до записи и повторно перед применением.
Путь не выбирается автоматически. MSIX/WindowsApps запрещён; отдельная копия приложения не создаётся.
Переходы через junction/symlink/reparse point запрещены. Каталог резервных копий должен находиться вне приложения, на том же томе: подмена существующего файла использует атомарный `File.Replace`.
Другой том отклоняется до записи. DistPath также должен находиться вне приложения,
а BackupRoot — вне DistPath.

Единственные изменяемые файлы приложения:

| Источник | Назначение относительно AppPath |
| --- | --- |
| `dist/i18n-ru.js` | `resources/ion-dist/i18n-ru.js` |
| `dist/en-US.json` | `resources/ion-dist/i18n/en-US.json` |
| `dist/dynamic/en-US.json` | `resources/ion-dist/i18n/dynamic/en-US.json` |
| `dist/native-en-US.json` | `resources/en-US.json` |
| существующий HTML | `resources/ion-dist/index.html` |

В HTML сразу после единственного открывающего тега `head` вставляется только
`<script src="/i18n-ru.js"></script>`. Повторная установка не дублирует точную инъекцию.
Неоднозначная существующая инъекция или HTML без единственного `head` отклоняются.
HTML должен быть корректным UTF-8; существующий BOM сохраняется.
JSON проверяется синтаксически. Все четыре ресурса обязательны.

Установщик не завершает и не запускает процессы. Работающее приложение вызывает отказ;
нечитаемый путь процесса с именем Claude/Anthropic и ошибка инвентаризации также вызывают отказ.
Проверки процессов повторяются перед резервированием и перед каждой заменой.
Никаких изменений `~/.claude/CLAUDE.md`, разрешений/ACL, настроек, кэшей, ярлыков,
задач планировщика или auto-heal нет.

## Только просмотр плана

Команды ниже приведены как инструкция, не выполнялись против настоящего приложения.
Получите SHA-256 EXE отдельно в режиме только чтения и сохраните доверенное значение:

```powershell
Get-FileHash -LiteralPath 'C:\Users\20051\AppData\Local\Programs\Claude\claude.exe' -Algorithm SHA256
(Get-Item -LiteralPath 'C:\Users\20051\AppData\Local\Programs\Claude\claude.exe').VersionInfo.FileVersion
```

```powershell
# Замените <SHA256> на проверенное значение из 64 шестнадцатеричных символов.
.\scripts\install-localization.ps1 `
  -AppPath 'C:\Users\20051\AppData\Local\Programs\Claude' `
  -ExpectedVersion '2.37337.1' -ExpectedExeSha256 '<SHA256>' `
  -BackupRoot 'C:\Users\20051\Desktop\ClaudeDesktop\tests\temp\manual-backups' `
  -DryRun | ConvertTo-Json -Depth 6
```

Вместо `-DryRun` можно передать `-WhatIf`. Оба режима выполняют только чтение:
не создают резервных копий, каталогов, staging-файлов, журналов и файлов проверки записи.
План содержит путь, версию, хеш EXE и SHA-256 каждого файла до/после.
Проверка работающих процессов действует и в этих режимах: сначала вручную закройте приложение,
если намерены запускать план. Во время текущей разработки этого делать не требуется.
Отсутствие этих ключей означает реальное применение; не запускайте такой вариант без отдельного решения.

## Резервирование и откат

В BackupRoot создаётся уникальный `localization-<GUID>`:

- `manifest.json`: абсолютные пути, версия, хеши, состояние операции;
- `<номер>.original`: побайтовая копия существовавшего файла;
- `<номер>.staged`: подготовленные новые байты;
- `<номер>.staged.replaced`: предыдущий файл при атомарной замене.

До первой модификации приложения все исходные файлы скопированы и проверены по SHA-256,
все новые байты подготовлены и проверены. Хеши назначения повторно проверяются перед заменой.
При исключении восстанавливаются изменённые существовавшие файлы, удаляются добавленные файлы
и созданные пустые каталоги приложения. Резервная копия сохраняется для расследования.
`Installed`, `RolledBack`, `RollbackFailed` фиксируются в манифесте; ошибка возвращается вызывающей стороне.
При `RollbackFailed` сообщение перечисляет ошибки и путь сохранённых оригиналов — восстановление
нужно выполнить вручную при закрытом приложении, сверяя `Before` в манифесте.
Если уже отказала запись самого манифеста, её ошибка также указана в сообщении.

Это транзакция с компенсацией исключений, не файловая транзакция Windows:
отключение питания/принудительное завершение установщика не гарантируют автоматический откат.
Атомарность действует для одного файла, не для всего набора. Проверки процесса не могут полностью
устранить гонку с внешним запуском приложения/обновлением: не запускайте приложение и обновление
до окончания операции. Метаданные файлов, ACL и альтернативные потоки не изменяются намеренно,
но откат гарантирует содержимое обычных файлов, а не побайтовый образ файловой системы.

## Восстановление после успешной установки

В том же файле есть отдельная функция `Restore-Localization`. Она использует только манифест
успешной установки `Installed` и его пять строго разрешённых путей. Версия/хеш EXE,
текущие установленные файлы и все резервные оригиналы проверяются до записи.
Изменённое обновлением приложение, изменённый оригинал или работающий процесс вызывают отказ.
Функция не удаляет резервную копию и не меняет её манифест.

```powershell
. .\scripts\install-localization.ps1
# Подставьте точный BackupPath из результата установки, не каталог BackupRoot.
Restore-Localization -BackupPath 'C:\path\localization-<GUID>' -DryRun
Restore-Localization -BackupPath 'C:\path\localization-<GUID>' -WhatIf
# Только после проверки плана, при вручную закрытом приложении:
Restore-Localization -BackupPath 'C:\path\localization-<GUID>' -Confirm
```

Восстанавливаются байты оригиналов; добавленный файл удаляется. Пустые каталоги, оставшиеся
после успешной установки, сохраняются (чужие каталоги не удаляются). При исключении восстановление
компенсируется возвратом уже затронутых файлов к установленному состоянию; ошибки компенсации
явно сообщаются. Это также не защита от аварийного выключения питания.
Повторный restore намеренно отказывает: текущие хеши уже не равны `After`.
Этот путь проверен тестом полного цикла установки/восстановления на искусственном приложении.

Для read-only инвентаризации работающего приложения достаточно команд чтения метаданных EXE
из раздела выше: их можно выполнять без закрытия приложения. Сам `DryRun` установки
намеренно сохраняет запрет работающих процессов.

## Тесты

```powershell
$result = Invoke-Pester -Script .\tests\install-localization.Tests.ps1 -PassThru
if ($result.FailedCount) { exit 1 }
```

Тесты совместимы с установленным Pester 3.4.0. Они создают уникальные искусственные каталоги
только внутри `tests/temp`, подменяют метаданные версии и инвентаризацию процессов,
не читают конфиги с секретами и не обращаются к установленному приложению.
Проверяются режимы без записи, точный список ресурсов, хеши и резервные копии,
повторная установка, работающие/неопознаваемые процессы, ошибка инвентаризации,
неверная версия/хеш, неполные/некорректные ресурсы, HTML и откат при моделируемом сбое.
Искусственные каталоги удаляются после каждого теста.
